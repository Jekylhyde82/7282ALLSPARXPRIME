## Experimental evidence still missing

1. No authentic baseline or architecture-assisted raw model responses have been captured in the repository.
2. No independent blinded scoring has been performed.
3. No independent adversarial review has been performed.
4. No reviewer identity or evidence provenance has been independently authenticated.
5. No measured comparison report exists.
6. The current protocol/documentation specifies ten records (five cases × two conditions), but the latest experimental requirement calls for three repetitions per case per condition: **30 trials total**. The runner and acceptance gate must be upgraded to support and require those repetitions before any final comparison.
7. The in-repository validator is a documented subset of JSON Schema Draft 2020-12, not a standards-compliant implementation. A pinned standards-compliant validator remains a release prerequisite.
8. The current comparison runner accepts a single pair per case and does not enforce repetition completeness or aggregate repeated trials. This is a known acceptance defect.

## Experimental validity controls

- Preserve identical canonical task prompts across conditions; record the exact prompt hash.
- Hold model identity, tool access, context, temperature/settings (where exposed), and information availability constant.
- Randomize and blind response labels before scoring.
- Use the same independent blinded scorer across each paired comparison, with a separate independent adversarial reviewer.
- Keep raw responses immutable; retain provenance, timestamps, prompt hashes, model/settings metadata, and evidence references.
- Do not manufacture missing outputs, scores, assessor attestations, reviewer identities, or evidence.
- A run conducted in a context already exposed to the architecture cannot be treated as an uncontaminated baseline. Baseline capture must occur in a genuinely isolated fresh context with architecture-specific memory/instructions absent; otherwise mark the trial invalid.
- A model-generated self-score is not independent scoring. The implementation team cannot independently approve its own release.
